Smoke Test - How Threads Work (learning notes)
==============================================

These examples teach the pieces. They are NOT the smoke test itself -
combine them yourself (about 10 lines).


1. WHAT A THREAD IS
-------------------
A normal program runs one line after another. A thread is a second line
of execution running at the same time as main. In C++ it comes from
<thread>.


2. STARTING ONE THREAD
----------------------
    #include <iostream>
    #include <thread>

    void sayHello() {
        std::cout << "hello from a thread\n";
    }

    int main() {
        std::thread t(sayHello);   // starts running sayHello() right now, in parallel
        t.join();                  // main waits here until sayHello() finishes
        std::cout << "main is done\n";
    }

- std::thread t(sayHello);  creates the thread and it starts immediately.
- t.join();  means "wait for t to finish". Remove it and the program
  crashes (std::terminate), because C++ won't let a thread object be
  destroyed while its thread is still running.


3. GIVING A THREAD AN ARGUMENT
------------------------------
    void greet(int n) {
        std::cout << "I got the number " << n << "\n";
    }

    std::thread t(greet, 42);   // extra arguments are passed to the function


4. WHY JOIN CONTROLS THE ORDER
------------------------------
    std::thread t(sayHello);
    std::cout << "A\n";   // can print before OR after the thread's message
    t.join();
    std::cout << "B\n";   // ALWAYS after the thread's message

Once join() returns, the thread is guaranteed to have finished, so
anything after the join always comes after the thread's output.
(This is the "explain why" question for the demo.)


5. HANDLING ERRORS
------------------
Creating a thread can fail (e.g. the OS is out of resources). C++ then
throws an exception:

    #include <system_error>

    try {
        std::thread t(sayHello);
        t.join();
    } catch (const std::system_error& e) {
        std::cerr << "thread creation failed: " << e.what() << "\n";
        return 1;
    }

THINGS THAT LOOK ODD BUT ARE NORMAL
-----------------------------------
- The two workers may print in a different order each run. The OS
  decides which thread runs first.
- Their lines can sometimes run together on one line, because both
  threads write to cout at once. Fix: lock a std::mutex around the
  print (see src/EnvironmentTest.cpp for the pattern).
