PHASE 1 - Controlled race and repair            (Nov 16-17, ~3 h)  [15 pts]
--------------------------------------------------------------------------
Spec Section 3. Concepts I must be able to explain in my own words:
  - Shared counter is std::atomic<int> = 0. Each worker does load (into a
    private temp), adds 1 locally, then stores. Use load/store, NOT fetch_add.
  - Forced version: a gate (std::barrier, or a mutex+CV handshake) placed
    AFTER both reads and BEFORE either write guarantees both read 0.
    Final value is always 1. Do not use sleep or rely on lucky timing.
  - Repaired version: one std::mutex around the whole read-add-write.
    Final value is always 2. No barrier inside the locked region. Be able to
    explain why one there would deadlock: worker A holds the lock and waits
    at the barrier for B, while B waits for the lock.
[ ] Implement both versions (separate programs or one program with a mode).
[ ] Print a NUMBERED trace: step#, worker, READ/WRITE, private value, and the
    final counter. Protect the printing so lines do not interleave.
[ ] Save the outputs to evidence/race/forced_output.txt and
    evidence/race/repaired_output.txt. Keep these separate from events.csv.
    Run each several times and confirm the result never changes.
[ ] Draft notes: why 1 is guaranteed, why atomic load/store does not make
    the increment atomic, and the deadlock argument. Note where the gates and
    locks are in the source (line numbers go in the report later).
[ ] Commit.

PHASE 3 - Condition-variable queue              (Nov 19-20, ~5 h)  [30 pts]
-------------------------------------------------------------------------
Spec Sections 4-5. Build the bounded FIFO queue myself (for example a
circular buffer, see design.txt). Do not use a library blocking queue,
thread pool, or one global lock around the whole workload.
[ ] One queue mutex protects: buffer, occupancy, event log, seq, stats.
[ ] put: lock, then `while (occupancy == capacity) not_full.wait`. Insert,
    log ENQ/STOP_ENQ, notify not_empty while still holding the lock, unlock.
[ ] get: lock, then `while (occupancy == 0) not_empty.wait`. Remove the
    head, log DEQ/STOP_GET, notify not_full, unlock.
[ ] Consumer loop: get, then unlock. Sleep units*delay_ms only if
    delay_ms > 0. Compute the result OUTSIDE the lock. Lock, log DONE
    (occupancy unchanged), update the stats, unlock. Then take the next record.
[ ] Lifecycle: start ALL consumers and producers, then join all producers.
    MAIN puts STOP1..STOPC through the same put(). Join all consumers, then
    print the summary.
[ ] A consumer exits ONLY after STOP_GET, never because the queue is empty.
[ ] Catch std::system_error from thread creation and lock operations.
[ ] Run the public case 10+ times and confirm that the counts equal 6 and the
    sum is 3852 every time. Also check that the event count is 3*jobs + 2*C.
[ ] Commit. (If a real bug shows up here, SAVE THE EVIDENCE NOW. It can
    become investigation #1, see Phase 7.)


PHASE 4 - Semaphore queue                       (Nov 21, ~3 h)  [20 pts]
-----------------------------------------------------------------------
[ ] std::counting_semaphore: empty = capacity, full = 0, plus the same mutex.
[ ] Producer: empty.acquire(), lock, insert + log, unlock, full.release().
    Consumer: full.acquire(), lock, remove + log, unlock, empty.release().
    (Release the mutex BEFORE releasing the semaphore. Acquire the permit
    BEFORE locking. Be able to explain the deadlock when the order is reversed.)
[ ] STOP records go through the same permits. Use the same CSV and summary
    format as CV mode, and reuse the same workload, logging, and summary code.
[ ] Do not assert empty+full == capacity at every step. Do assert
    0 <= occupancy <= capacity.
[ ] Public case: same totals as CV mode. Commit.


PHASE 5 - Independent checker                   (Nov 22-23, ~5 h)  [8 pts]
-------------------------------------------------------------------------
Spec Section 6. A separate program (checker/) that reads ONLY the config
file and events.csv. It does not include or call the queue code. Writing its
own config parser is the safest choice.
Output: PASS + totals, exit 0. Or FAIL + event# (or EOF) + reason, nonzero exit.
Checks (one function each, so I can name them in the report):
[ ] config valid; header exactly "seq,actor,event,job_id,occupancy,result"
[ ] each row: 6 fields, known event, valid actor (P0..P(P-1), C0..C(C-1),
    MAIN), seq = 1,2,3,...
[ ] actor/event roles: ENQ only from producers. DEQ/DONE/STOP_GET only from
    consumers. STOP_ENQ only from MAIN.
[ ] job ID 1..jobs, and the ENQ comes from the owning producer ((j-1) mod P)
[ ] replay the FIFO: ENQ/STOP_ENQ append, DEQ/STOP_GET must match the head.
    Recorded occupancy == replay size, always within 0..capacity.
    DONE leaves occupancy unchanged.
[ ] per consumer: at most one job in progress. DONE must match that
    consumer's current job and the result formula. No DEQ/STOP_GET before
    the previous DONE.
[ ] exactly one ENQ, DEQ, DONE per real job. STOP1..STOPC, each enqueued once.
    No real ENQ after the first STOP_ENQ. Each consumer takes exactly one
    STOP and has no later events.
[ ] EOF: queue empty, no unfinished job, every job DONE, every consumer
    stopped, result_sum correct.
[ ] Hand-make small broken CSVs while developing to confirm each check
    fires. (These are my own unit tests, not the required corrupted copies.)
[ ] Commit.
