Invariants: how to write them yourself

What an invariant is

An invariant is a statement that is true every time the lock is not held. It can be briefly false inside put or get, between two lines of code. It must be true again before the mutex is released.

How to write one

Each invariant needs:
- a quantity, such as a variable or a count of events
- a relationship, such as <=, ==, or "before"
- a condition for checking it, such as "at every unlock" or "at the end of the trace"

An example from a different system, to show the form: a parking garage with N spaces.

▎ "The number of cars inside is always between 0 and N, and equals (cars that entered − cars that left)."

Notice that it's a single sentence, uses exact numbers, and you could check it against a log.

Questions to answer, one invariant (or two) per group

Capacity / occupancy
- What's the smallest count can ever be? The largest? Write it as a bound using capacity.
- How does count relate to the number of puts and gets so far?
- Does a STOP record take up a slot? (It does. Say so.)
- What does the occupancy column in the trace have to match?

FIFO order
- If job A is enqueued before job B, what must be true about when they are dequeued?
- Every get takes from which position?
- How would you check this using only the CSV? (Compare the order of ENQ rows with the order of DEQ rows.)

Exactly-once processing
- For each real job ID from 1 to jobs: how many ENQ rows, DEQ rows, and DONE rows should it have?
- Which events must come in which order for a single job?
- DONE has to come from the same consumer that did what?
- Which value can you check at the end? (Your Day 3 total of 3852 for the public case.)

Waiting rules (synchronization)
- When is a consumer allowed to be blocked? When is a producer?
- What must be true after a thread wakes up and before it touches the buffer?

STOP / shutdown
- How many STOP records in total?
- Can any STOP_ENQ appear before the last real ENQ?
- What can a consumer do after its STOP_GET?

Mutex scope
- Which variables may only be read or written while the mutex is held?
- What must never happen while it's held? (Your design section on processing outside the lock answers this.)

Good test for each sentence

Ask yourself: "Could my checker program test this automatically from events.csv?" If yes, it's a strong invariant. If it's vague ("the queue works correctly"), rewrite it.
